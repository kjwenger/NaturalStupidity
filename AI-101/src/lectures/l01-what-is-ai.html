Lecture 1 · Week 1 · Part I Classical AI

What is AI? Agents and environments

Four definitions of AI, a short history in three waves, and the one framework this whole course uses: the rational agent.

Learning objectives

  • Distinguish the four classic views of AI (thinking/acting × humanly/rationally).
  • Place symbolic AI, machine learning and deep learning on a timeline and explain why each wave rose and stalled.
  • Describe a task as an agent with a PEAS specification and classify its environment.
  • Name the main agent architectures, from simple reflex to learning agents.

1.1 Four ways to define AI

There is no single accepted definition of artificial intelligence. Russell and Norvig sort the historical definitions along two axes: whether they concern thinking or behaviour, and whether they measure success against human performance or against an ideal of rationality.

Human-likeRational
ThinkingCognitive modelling: build programs whose reasoning resembles human reasoning (cognitive science).Laws of thought: derive correct conclusions with formal logic.
ActingThe Turing test: behave so that a judge cannot tell machine from human.Rational agents: act to achieve the best expected outcome.

This course takes the bottom-right view. A rational agent is easier to define precisely than "human-like thinking", it covers logic as one tool among several, and it is how practitioners actually build systems: you state what counts as success and design the system to maximise it.

Turing 1950. Turing proposed his "imitation game" to replace the question "Can machines think?", which he considered too vague to be meaningful. Modern LLMs pass casual versions of it, which says more about the test than about thinking.

1.2 A short history in three waves

Symbolic AI (1956 – 1990s)

The 1956 Dartmouth workshop named the field. Early successes in theorem proving, game playing and toy-world planning led to great optimism. Knowledge was written by hand as symbols and rules; expert systems of the 1980s encoded thousands of if-then rules from human experts. They were brittle: every situation the rule-writers had not foreseen broke them, and maintaining large rule bases proved too expensive. Funding collapsed twice, in the so-called AI winters of the mid-1970s and late 1980s.

Statistical machine learning (1990s – 2012)

Instead of writing rules, systems learned them from data: spam filters, speech recognisers, recommender systems. Probabilistic methods (Bayesian networks, hidden Markov models) and kernel methods (support vector machines) dominated. Features still had to be designed by hand.

Deep learning (2012 – today)

In 2012 a convolutional network trained on GPUs (AlexNet) won the ImageNet competition by a wide margin. Neural networks learn their own features from raw data, and they keep improving with more data and compute. The Transformer (2017) made it possible to train very large language models, and since about 2022 these models are good enough to be general-purpose assistants and agents.

Example 1.1 (Three waves on one task)

Recognising handwritten digits. Symbolic: rules such as "a 1 is a vertical stroke". Statistical ML: hand-designed features (stroke counts, pixel histograms) fed to an SVM. Deep learning: raw pixels fed to a CNN that learns the features itself, with error rates below 0.3% on MNIST.

1.3 Agents

Definition 1.1 (Agent)

An agent is anything that perceives its environment through sensors and acts upon it through actuators. The sequence of everything it has perceived so far is its percept sequence. Its behaviour is described by the agent function, a mapping from percept sequences to actions, and implemented by an agent program.

Definition 1.2 (Rational agent)

For each possible percept sequence, a rational agent selects an action that is expected to maximise its performance measure, given the evidence of the percept sequence and whatever built-in knowledge it has.

Rational is not the same as omniscient or perfect. A rational agent can make a decision that turns out badly, as long as it was the best decision given what it knew. Rationality also includes information gathering: looking before crossing the road is the rational action.

PEAS: specifying a task

Before designing an agent, write down its task environment as PEAS: Performance measure, Environment, Actuators, Sensors.

Example 1.2 (PEAS for a coding agent)

A coding agent such as Claude Code running on a local LLM:

  • P: tests pass, the user's request is met, few wasted steps, no destructive actions.
  • E: a source repository, a shell, the user, the model server.
  • A: edit files, run commands, write messages to the user.
  • S: file contents, command output, user messages.

Environment types

Environments differ along several dimensions, and each one affects which methods work:

  • Fully vs. partially observable: can the sensors see the complete relevant state? Chess: fully. Poker, driving: partially.
  • Deterministic vs. stochastic: is the next state fully determined by the current state and action?
  • Episodic vs. sequential: do current decisions affect future ones? Classifying one image: episodic. Chess: sequential.
  • Static vs. dynamic: does the world change while the agent deliberates?
  • Discrete vs. continuous: states, time, percepts and actions.
  • Single vs. multi-agent: are there other agents, cooperative or competitive?
  • Known vs. unknown: does the agent know the rules (the transition model) of the environment?

The hardest case is partially observable, stochastic, sequential, dynamic, continuous, multi-agent and unknown. Driving a taxi is the textbook example.

1.4 Agent architectures

  1. Simple reflex agent: acts on the current percept only, with condition–action rules. Works only in fully observable environments.
  2. Model-based reflex agent: keeps an internal state that tracks the parts of the world it cannot currently see.
  3. Goal-based agent: considers the future: "what will happen if I do this, and does it get me to my goal?" This needs search and planning (lectures 2–3).
  4. Utility-based agent: replaces a yes/no goal with a utility function that rates how desirable a state is, so it can trade off conflicting goals and uncertainty.
  5. Learning agent: any of the above, plus a learning element that improves the agent from feedback. A critic judges performance, a problem generator suggests exploratory actions.

Today's LLM agents fit this scheme: the LLM is the agent program, the context window is the internal state, and tool calls are the actuators. Lecture 13 returns to this.

Summary

  • We define AI as the study of rational agents: systems that act to maximise expected performance.
  • AI has gone through symbolic, statistical and deep-learning waves; each solved its predecessor's main bottleneck.
  • PEAS and the environment dimensions tell you which methods a task needs.

Exercises (Sheet 1)

  1. Write a PEAS description for (a) a robot vacuum cleaner, (b) a spam filter, (c) a chess engine. [6 pts]
    Solution

    (a) P: floor area cleaned, energy used, collisions, time. E: rooms, furniture, dirt, people, pets. A: wheels, brushes, suction. S: bump sensors, cliff sensors, lidar or camera, dirt sensor, battery level.

    (b) P: accuracy, with false positives (good mail marked spam) weighted much higher than false negatives. E: incoming mail stream, senders, users. A: label as spam / not spam, move to folder. S: message headers, body text, attachments, user feedback.

    (c) P: games won, drawn, lost; Elo rating; time used. E: board, opponent, clock. A: moves. S: board state, opponent's moves, clock.

  2. Classify each environment from 1.1 along the seven dimensions of section 1.3. [6 pts]
    Solution

    Vacuum: partially observable, stochastic, sequential, dynamic, continuous, single-agent (people are part of the environment), partly known. Spam filter: partially observable (sender intent hidden), stochastic, episodic per message (though spammers adapt over time), static per decision, discrete, multi-agent in the adversarial sense (spammers), known. Chess: fully observable, deterministic, sequential, semi-dynamic (the clock runs), discrete, multi-agent competitive, known.

  3. "A rational agent never makes mistakes." True or false? Justify with an example. [3 pts]
    Solution

    False. Rationality maximises expected performance given the available evidence. An agent that crosses an empty road after looking both ways acts rationally even if a meteorite then hits it; the outcome was not foreseeable from its percepts.

  4. Why did the expert systems of the 1980s fail to scale? Name two reasons and say how machine learning addresses each. [4 pts]
    Solution

    (1) The knowledge-acquisition bottleneck: rules had to be elicited from experts by hand, which was slow and expensive. ML learns the mapping from examples instead. (2) Brittleness: rules failed silently outside the situations their authors foresaw, and rule interactions became unmanageable. Learned models generalise statistically and degrade more gracefully, and they can be retrained when the data changes.
